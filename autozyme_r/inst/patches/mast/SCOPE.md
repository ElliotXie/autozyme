## `MAST::zlm + MAST::lrTest`

- **In-scope output equivalence:** tolerance
- **Validated at:** `zfit <- MAST::zlm(formula = ~ group + cngeneson, sca = <data>, method = "bayesglm", ebayes = TRUE, parallel = TRUE, silent = TRUE); lrt <- MAST::lrTest(zfit, CoefficientHypothesis("groupB"))  [reference baseline uses parallel = FALSE, options(mc.cores = 1L); patched/headline reported at single-thread mc.cores = 1]`
- **Supported scope:** The fast path is an APPROXIMATION (explicitly not bit-exact; documented in CHANGELOG/final_audit). Four namespace overrides on MAST internals: (1) fast_validateState strips IRLS sanity checks down to the convergence test; (2) fast_bgf no-ops family$validmu/$valideta and loosens the IRLS epsilon from 1e-8 to 1e-5 for ALL families and ALL fits; (3) fast_updateState by default delegates to MAST's original updater (the native C++ cpp_updateState path is gated OFF behind getOption('autozyme.mast.native_update_state') / env AUTOZYME_MAST_NATIVE_UPDATE_STATE=1, because it segfaults under package attest) -- the C++ kernel only handles binomial+logit and gaussian+identity with all(state$good)==TRUE; (4) fast_lrTest_hybrid: a two-pass hybrid that computes a cheap Wald statistic for every gene (chisq df=1 for cont/disc, df=2 for hurdle) then runs the EXACT upstream lrTest only on the top-K=200 genes ranked by Wald hurdle p-value, overwriting those K rows with exact LR results. lrTest fast path activates only for hypothesis of class CoefficientHypothesis or a length-1 character that resolves to exactly one matching column name in coefC. Correct/accepted regime as benchmarked: bayesglm method, a single-coefficient (1 df per component) contrast on a model with discrete+continuous (hurdle) components, where DE conclusions are driven by top-ranked genes (top-100 jaccard ~1, pearson on coef and -log10 p ~1; max coef deviation ~1e-4). The loosened 1e-5 epsilon and stripped validators apply unconditionally to all genes/families on the IRLS path.
- **Out-of-scope behavior:** ⚠ **Documented approximation.** Correct for the validated configuration below; results may differ outside it and there is no automatic fall-back, so stay within the stated scope (or deactivate the patch).
- **Approximation details:** NOT bit-exact: relaxed IRLS epsilon 1e-8 -> 1e-5 (fast_bgf, patch.R:59) shifts every coefficient (~1e-4 observed); silently applied to ALL families/fits with no guard ; fast_bgf no-ops family$validmu and family$valideta for ALL families (patch.R:54-55) -- IRLS divergence/out-of-domain mu/eta that upstream would catch is silently ignored ; fast_validateState removes 5 of 6 sanity/boundary checks, keeping only the convergence test (patch.R:41-48) -- boundary/non-finite-deviance conditions upstream guards against are no longer detected ; lrTest hybrid only returns EXACT LR p-values for the top-K=200 genes by Wald rank; all other genes get a WALD approximation, not a likelihood-ratio test (patch.R:191-227). If a truly significant gene falls outside the top-200 Wald ranks, its reported p-value/lambda/df differ from upstream LR (silent_possibly_wrong for ranks > K) ; K is hard-coded to 200 in the SHIPPED patch (patch.R:191), with NO tier-adaptivity -- unlike the task pipeline which used tier-adaptive .K_BY_TIER (200/150/100). For datasets with >200 truly-tested genes, more genes get only-Wald results ; Wald hybrid assumes a 1-df-per-component contrast: cont df=1, disc df=1, hurdle df=2 are hard-coded (patch.R:189,206-209,221-223). Multi-coefficient / multi-df hypotheses passed as CoefficientHypothesis are NOT correctly handled by the Wald branch (df assumptions wrong) ; lrTest fast path requires the term name to match exactly one column in object@coefC; falls back to upstream for class-Hypothesis (non-CoefficientHypothesis) or ambiguous/zero matches (patch.R:166-176) -- safe fallback there ; native cpp_updateState path (gated off by default) hard-codes binomial+logit and gaussian+identity ONLY, and requires all(state$good)==TRUE (patch.R:80); other families fall through to an R reimplementation, and the kernel is disabled by default because it segfaults ; parallel=TRUE relies on parallel::mclapply (fork-only): on Windows it silently degrades to serial; tier-aware mc.cores caps (patch.R:38-39) are an additional config the smoke harness injects, not part of the user-facing override
